# 伴随开发排程

Normify区分三类顺序。

| 数据 | 表达内容 | 不表达内容 |
| --- | --- | --- |
| 模块 `deps` | 调用与数据依赖 | 开发前置 |
| 布局 `order` | 图谱阅读顺序 | 开发工期 |
| 变更 `schedule` | 任务前置与冲突 | 自动执行与工期承诺 |

排程复用原31个工具。
它不另建模块架构树。
它不改模块UID或依赖。
它不安装或改写用户技能。

## 一、登记任务

每项开发任务使用一个变更。
`schedule`采用可选字段。
新排程默认采用`proposed`。
未登记旧变更保持原行为。

| 字段 | 格式 | 含义 |
| --- | --- | --- |
| `depends_on` | 变更ID数组 | 显式开发前置 |
| `phase` | 字符串 | 人工阶段标签 |
| `owner` | 字符串 | 负责人标签 |
| `files` | 相对路径数组 | 计划写入范围 |
| `resources` | 字符串数组 | 独占逻辑资源 |
| `priority` | 0至100整数 | 就绪任务排序提示 |

变更的`modules`表达模块范围。
排程不复制该模块清单。
父模块范围覆盖其子模块。
引擎补充模块源码范围。
`files`只能引用仓库内路径。
目录前缀也算写入范围。
路径重叠会产生冲突。
引擎忽略路径字母大小写。
写入路径不支持glob。
资源名采用显式共享约定。
例如`gpu:0`表示独占GPU。
引擎不检测真实设备占用。

先建立相关模块契约。
再调用`normify_change_open`。
以下示例假设模块已存在。

```json
{
  "project": "demo",
  "id": "2026-10-11-core",
  "title": { "zh": "完成核心实现", "en": "Implement core" },
  "intent": { "zh": "冻结核心契约", "en": "Freeze the core contract" },
  "modules": { "modify": ["demo.core"] },
  "acceptance": ["目标测试通过", "架构校验零错误"],
  "schedule": {
    "depends_on": [],
    "phase": "P1",
    "owner": "engine",
    "files": ["src/core/"],
    "resources": ["gpu:0"],
    "priority": 10
  }
}
```

继续登记后续任务。
以下示例也调用`normify_change_open`。

```json
{
  "project": "demo",
  "id": "2026-10-11-query",
  "title": { "zh": "接入查询入口", "en": "Integrate query entry" },
  "intent": { "zh": "复用已验收核心", "en": "Use the verified core" },
  "modules": { "modify": ["demo.query"] },
  "acceptance": ["查询专项通过", "接口兼容检查通过"],
  "schedule": {
    "depends_on": ["2026-10-11-core"],
    "phase": "P2",
    "owner": "query",
    "files": ["src/query.rs"],
    "resources": ["gpu:0"],
    "priority": 5
  }
}
```

模块依赖不自动创建前置。
阶段标签也不创建前置。
优先级不越过前置或冲突。
较小优先级优先排序。
默认优先级采用50。

## 二、前置与并行门禁

前置只接受`verified`状态。
`abandoned`不满足前置。
缺失前置会阻断校验。
依赖环也会阻断校验。
任务不能引用自身。

并行任务须避免三类重叠：

1. 模块写入范围。
2. 文件与目录写入范围。
3. 独占逻辑资源。

任一重叠都阻止同时运行。
任务进入`in_progress`前须检查。
未满足前置也禁止开始。

引擎只判断登记信息。
遗漏范围会造成错误许可。
人工仍须核对共享接口。
人工仍须核对运行资源。
零冲突不证明产品验收。

## 三、查询与开始

调用`normify_change_list`查看排程。
查询时传`view:schedule`。
调用`normify_brief`查看开发指引。
两者保持只读查询。

```json
{ "project": "demo", "view": "schedule" }
```

简报须显式包含排程。
以下示例调用`normify_brief`。

```json
{ "project": "demo", "include_schedule": true }
```

确认任务就绪后开始。
以下示例调用`normify_change_update`。

```json
{
  "project": "demo",
  "id": "2026-10-11-core",
  "patch": { "status": "in_progress" }
}
```

变更接口会检查排程门禁。
人工改JSON后仍须校验。
工具不提供防篡改证明。
更新`schedule`会整体替换。
接口禁止移除既有排程。
验收关闭须使用收尾工具。
运行时冻结写入与前置声明。
这包括模块、文件与资源。
放弃后的排程任务不得复活。
`normify_validate`检查整体状态。
`normify_build`拒绝错误计划。

实现后先运行目标测试。
再调用`normify_change_close`。
提供真实的绝对`repoRoot`。
架构收尾不替代产品测试。
后续任务等待前置完成。

## 四、流程图与产物

需要冻结产物时构建。
调用`normify_build`。
以下参数使用示例仓库路径。
调用时须换成真实绝对路径。

```json
{ "project": "demo", "repoRoot": "C:/work/demo" }
```

只看实时图无需构建。
直接调用`normify_render`。

```json
{ "project": "demo", "view": "schedule" }
```

| 产物 | 内容 |
| --- | --- |
| `schedule.json` | 冻结任务与派生排程 |
| `schedule.md` | 可读开发顺序表 |
| `schedule.mmd` | Mermaid流程图源码 |
| 本机交互地址 | 实时排程与缩放拖动 |

构建回执冻结前三项哈希。
排程渲染不再输出HTML文件。
工具只返回本机交互地址。
页面刷新读取实时输入。
看图不要求构建或回执。
它不改变任务与模块状态。
实时图不充当冻结验收。
无排程构建不删除旧产物。
旧产物不能充当当前证据。

默认视图仍显示架构。
下面调用保持原有行为。

```json
{ "project": "demo", "view": "architecture" }
```

排程视图拒绝`out`。
旧HTML输出调用须迁移。
架构`out`仍限定项目路径。
默认架构文件名为`normify.html`。
排程网页不加载外部依赖。
服务只监听`127.0.0.1`。
链接携带随机访问令牌。
服务拒绝跨源读取与写请求。
服务随MCP进程退出。
链接失效时重新调用渲染。
仅明确要图时打开网页。
进度询问使用只读汇报。
查看器采用图优先布局。
整屏白底画布承载流程图。
两条工具栏集中查看操作。
详情区默认隐藏。
点选节点后展开详情。
展开后，右栏宽310像素。
宽度至多700像素时。
详情区占底部35%。
关闭详情归还画布空间。
详情按钮可查看诊断。
用户可切换三种模式(mode)。

| 模式 | 用途 |
| --- | --- |
| 准入主线 | 压缩真实任务依赖 |
| 阶段任务 | 查看阶段与外部前置 |
| 完整依赖 | 查看全部任务与前置 |

三种视图默认从上向下。
依赖层决定纵向位置。
同层任务沿横向展开。
箭头从前置指向后继。
主线不折行回绕。
布局不虚构阶段串行关系。

阶段下拉框选择阶段。
定位下拉框跳转任务。
用户可缩放与拖动画布。
节点支持回车与空格。
详情跳转也支持键盘。
详情区保留完整前置。
它区分状态与派生就绪。
阻断不改变任务状态。
它另列写入与资源范围。
历史进行态仍可阻断任务。
历史占用开关只改变图示。
它不解除阻断或放开门禁。

完整图实线表示显式前置。
完整依赖包含全部任务。
主线实线投影真实依赖路径。
主线不保证显示每项任务。
阶段图保留直接外部前置。
详情区列出原始完整前置。
阶段标签不规定串行顺序。
橙色虚线表示登记冲突。
颜色区分派生就绪状态。
图中前置层不是开发波次。
预测波次独立于图中分层。
图中分叉不授予并行许可。
任务验收态(verified)。
它不证明产品验收。

## 五、预测波次的边界

波次描述未来集成顺序。
同波任务没有登记冲突。
波次不承诺实际工期。
排程不自动执行任务。
排程不自动分配代理。
排程不锁定操作系统资源。

未登记任务不获自动许可。
旧进行态任务可能阻断新任务。
共享状态须先分配写入责任。
性能测试须登记独占GPU。
并行完成后仍须集成验收。

## 六、兼容边界

项目继续保留31个MCP工具。
未登记排程时沿用旧语义。
旧变更文件无需增加字段。
旧架构产物无需迁移。
构建只为登记项目增加排程。
用户配置与技能安装保持独立。
