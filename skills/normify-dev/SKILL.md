# Normify 伴随开发

## 使用边界

先读取仓库指引。
用户指令优先。
仅修改用户授权的源码。
先确认已有结构目录。
无结构项目时勿强制接管。
需要新建架构时用 `$normify-gen`。
禁止虚构测试与验收证据。

## 只读进展触发

询问进度时先走只读流程。
不要开启开发变更。
优先使用进展钩子快照。
钩子监听`UserPromptSubmit`。
需单独安装并信任。
它汇总排程、Git与源码证据。
它仅读取代码图谱索引。
它不初始化或刷新索引。
缺少凭据时报告未验收。
过期图谱不证明当前源码。
`verified`不等于产品验收。
区分历史证据与本次实测。
先给结论，再列进展与缺口。

没有快照时先取简报。
工具：`normify_brief`。
传`include_schedule:true`。
只补查相关Git与验收凭据。
不要扫描全部文档。
不要跑产品测试。
不要改模块、排程或验收状态。
不要自动构建或渲染。
不要把任务数算成完成率。

用户明确要图时再渲染。
工具：`normify_render`。
传`view:schedule`。
再打开返回的本机地址。
不要传`out`或用文件预览。
服务退出时重新调用工具。

## 开始任务

确认 `normify` 服务连接。
使用绝对 `repoRoot` 路径。
用 `dir` 或 `project` 定位结构。
先读取相关模块与规则。
记录目标与涉及模块。
验收条件应描述可检查事实。
引擎收尾不替代产品测试。

| 动作 | 工具 |
| --- | --- |
| 开启变更 | `normify_change_open` |
| 获取开发指引 | `normify_brief` |
| 预检设计 | `normify_check` |
| 建立计划态 | `normify_module_batch` |

规则违规时先调整设计。
不要削弱规则来绕过错误。
先建立计划态模块。
再逐个实现其接口。

## 开发顺序与并行

先读取既定开发路线。
不要从架构依赖推断前置。
不要把阅读顺序当开发顺序。
变更使用可选`schedule`字段。
用`depends_on`登记任务前置。
前置只接受`verified`状态。
`abandoned`不满足前置。
新排程默认采用`proposed`。

登记模块与相对写入路径。
目录前缀也算写入范围。
用`resources`登记独占资源。
性能测试须登记独占GPU。
模块、文件或资源重叠禁并行。
未登记旧任务不获并行许可。
人工仍须核对接口与资源。

查询用`normify_change_list`。
排程查询传`view:schedule`。
指引用`normify_brief`。
简报传`include_schedule:true`。
确认就绪后更新进行态。
工具：`normify_change_update`。
不要直接改JSON绕过门禁。
实施前仍须完成设计预检。

图谱复用原31个工具。
架构图先运行`normify_build`。
排程图使用实时只读数据。
再用`normify_render`。
排程视图传`view:schedule`。
默认视图仍显示架构。
排程页面刷新后更新数据。
预测波次不承诺工期。
排程不自动执行或派发任务。

详细字段用`normify_help`。
主题：`schedule`。

## 开发与同步

完成模块后刷新源码证据。
仅激活已经落地的模块。
结构变化时同步受影响布局。
连续编辑后检查源码漂移。
建议每八次编辑检查一次。
配套钩子支持自动提醒。
需另行安装并信任钩子。
它每八次成功编辑提醒。
它不自动改写架构。
它不替代预检或测试。
不要将提醒视作自动门禁。

| 动作 | 工具 |
| --- | --- |
| 修改模块 | `normify_module_patch` |
| 移动模块 | `normify_module_move` |
| 刷新证据 | `normify_module_refresh` |
| 检测漂移 | `normify_sync` |
| 更新布局 | `normify_layout_upsert` |

## 收尾

先运行项目对应测试。
如实记录失败与未运行项。
随后执行变更收尾。
工具：`normify_change_close`。
只在需要时开启渲染。
检查错误数量与变更状态。
仅在零错误时报告完成。
报告警告与真实产物路径。

需要参数时调用帮助工具。
工具：`normify_help`。
主题支持 `tool:<工具名>`。
不要猜测接口或手算指纹。
