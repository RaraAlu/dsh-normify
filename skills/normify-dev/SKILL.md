# Normify 伴随开发

## 使用边界

先读取仓库指引。
用户指令优先。
仅修改用户授权的源码。
先确认已有结构目录。
无结构项目时勿强制接管。
需要新建架构时用 `$normify-gen`。
禁止虚构测试与验收证据。

## 开始任务

确认 `normify` 服务连接。
使用绝对 `repoRoot` 路径。
用 `dir` 或 `project` 定位结构。
先读取相关模块与规则。
记录目标与涉及模块。
验收条件应描述可检查事实。
引擎收尾不替代产品测试。

| 动作 | 工具 |
| --- | --- |
| 开启变更 | `normify_change_open` |
| 获取开发指引 | `normify_brief` |
| 预检设计 | `normify_check` |
| 建立计划态 | `normify_module_batch` |

规则违规时先调整设计。
不要削弱规则来绕过错误。
先建立计划态模块。
再逐个实现其接口。

## 开发与同步

完成模块后刷新源码证据。
仅激活已经落地的模块。
结构变化时同步受影响布局。
连续编辑后检查源码漂移。
建议每八次编辑检查一次。
配套钩子支持自动提醒。
需另行安装并信任钩子。
它每八次成功编辑提醒。
它不自动改写架构。
它不替代预检或测试。
不要将提醒视作自动门禁。

| 动作 | 工具 |
| --- | --- |
| 修改模块 | `normify_module_patch` |
| 移动模块 | `normify_module_move` |
| 刷新证据 | `normify_module_refresh` |
| 检测漂移 | `normify_sync` |
| 更新布局 | `normify_layout_upsert` |

## 收尾

先运行项目对应测试。
如实记录失败与未运行项。
随后执行变更收尾。
工具：`normify_change_close`。
只在需要时开启渲染。
检查错误数量与变更状态。
仅在零错误时报告完成。
报告警告与真实产物路径。

需要参数时调用帮助工具。
工具：`normify_help`。
主题支持 `tool:<工具名>`。
不要猜测接口或手算指纹。
